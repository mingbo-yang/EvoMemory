# 逐题在线记忆机制进化

实验直接在预先登记的官方测试题流上作答和进化。MATH 使用符合整数判分条件的代数题、数论题，APPS 使用函数调用题、标准输入输出题。每个数据集各自从基线代码及空记忆开始。Executor 使用本地 Qwen3.8-27B。MATH 与 APPS 每次尝试生成一个答案。ALFWorld 使用 EvoMemBench CrossEp-Emb 的官方测试实例和 ALMA 的多步动作循环，每次尝试最多生成 30 次动作，读取环境记录的原生奖励。该设置评估 EvoMemory 在这些实例上的表现，与论文排行榜协议分别报告。Fixed Evolver 修改实现 `on_event(state, event, context)` 的 Task Memory 机制代码，Reviewer 负责诊断、解释证据和决定是否继续修改。

1. **选择当前题型的 Task Memory，保存题前检查点。** 代码在同一数据集的题型间继承；题面、作答、实际存储和学习经历按题型隔离。若切回旧题型时机制代码已变，则按新代码重建该题型此前的经历。
2. **首次作答。** 机制收到任务开始和作答前的事件。Executor 的系统消息接收作答前最终生效的记忆槽，用户消息携带原题。MATH 评分器核验最终整数，APPS 使用原生用例评分。作答后，反馈和结束事件仍可改变本次尝试的临时记忆状态。首次成功直接提交本题经历，进入下一题。
3. **首次失败后保证一次修改机会。** Reviewer 根据当前代码、读写行为、首次作答和判分证据给出初始诊断。框架检索本题开始前已经入库的修改经验，Evolver 结合诊断和当前代码提交候选。系统向 Evolver 提供可用模型及调用接口，由其自行决定机制的实现和交互时机。
4. **同一道题验证。** 候选通过接口、语言与隔离检查后，在相同题面、Actor 预算和种子上重新作答。各次使用相同的题前该类型经历；候选可按新的内部表示重新处理这些经历。当前题的尝试不写进这份起点。判分后 Reviewer 比较实际行为、原生分数及日志。
5. **每份候选得到一个决定。** 后审结合本题历轮变化、实际验证结果和已投入的成本给出依据。采纳要求候选合法、原题实测由 0 变 1，并能用当前证据说明机制的优点。续修时，上一轮后审直接指导下一份草稿，Evolver 收到上一份草稿或原始无效回复、精确错误、验证证据及 Reviewer 希望下一轮检查的问题。停止时保留父机制。单题修改次数和整批成本均无固定上限。候选未通过契约检查时，原生分数记为空，Reviewer 可以判断续修或停止。模型服务故障等基础设施问题会暂停该条流，由收据定位。
6. **结题时发布。** Task Memory 每题只提交一份本类型经历。首答正确时提交首答，采纳时提交该候选的作答，停止时提交原机制的首次失败经历。本题各轮的草稿、判分、审核意见先写入本题档案，下一轮通过题内交接读取。检索池始终只使用此前已经结题的记录。结题后，本题每次修改产生一条紧凑经验，一并发布到本数据集的 Evolution Memory。首答正确的题没有修改记录。

跨题的修改经验提供结构化代码差异片段、问题、聚合分数、规范意见及证据引用。题内档案保有完整代码与反馈。共享片段保留接口结构，为非协议字面量和命中题目私有文本的标识符生成局部别名，省去注释。Executor 只接收当前题型机制交付的记忆内容。参考答案和 APPS 私有测试数据由评分器使用。

**成本的时间点。** 每次后审看到此前已返回的 Reviewer 调用、本轮在内的 Evolver 调用，以及本题首答、候选作答和机制调用可选模型的实际用量。作答前记忆槽、题面、模型、参数和种子等绑定为同一请求时，Actor 复用原始作答收据。逻辑调用增加，物理推理消耗的 token 只累计一次。角色账本及逐题执行账本标记缺失用量。当前后审自己的消耗在响应后进入原始账本，若续修，从下一轮起可见。恢复同一已完成测量时读取原有收据。

## 运行

在项目根目录使用研究 Python 环境。预览只读公开题目元数据，输出各题型实际数量和题序哈希。默认取全部合格题，`--per-family` 可在运行前限定每个题型的数量。

```bash
python -m math_apps_online plan math --per-family 8
python -m math_apps_online plan apps --per-family 8
python -m math_apps_online plan alfworld --per-family 2
python -m math_apps_online run math --per-family 8 --output runs/online_math_adaptive_seed11
```

此服务器的 APPS 原生评分器将临时文件写在 `/tmp`。旧批次曾因系统盘空间耗尽中断。APPS 在独立临时挂载中运行；研究输出仍写入项目目录。

```bash
bwrap --bind / / --dev-bind /dev /dev --tmpfs /tmp --setenv TMPDIR /tmp -- \
  python -m math_apps_online run apps --per-family 8 --output runs/online_apps_adaptive_seed11
```

公开版本仅连接显式配置的本地模型服务；不启动、停止或排空已有服务。新版使用新的输出目录，相同登记的运行可以恢复。两组使用相同题序、初始机制、种子和 Reviewer 规则，各自记录实际成本。默认 `cross_type_em` 可检索本数据集所有已归档的修改经验；`--condition no_external_em` 仅允许当前题型的修改经验。

## 结果口径

- `first_correct / completed` 是未看本题反馈时的首次正确率。
- `solved / completed` 是包括获反馈后原题重试的解决率。某次候选答对但 Reviewer 未通过，该题仍可记作曾解决，机制保持原部署直至满足采纳条件。
- `correct_by_attempt[k]` 是本次运行中截至第 k 次修改曾答对的题数，k=0 对应首答。`proposals_by_attempt`、`native_comparisons_by_attempt`、`adoptions_by_attempt`、`stops_by_attempt` 的第一个元素对应第一次修改。各数组按实际轮数扩展，第 4 次及以后的收益和消耗单独可查。
- `solved_on_retry_without_adoption` 记录首答失败、重试曾经答对、最终保留原机制的题数。成本以实际模型账本为准，相同请求复用时区分逻辑作答和物理调用。
- 原题从 0 变 1 能证明该次重试答对。跨题迁移需要比较相同题序下两组在后续题、尤其是新题型上的首次表现，并同时报告各组投入的修改次数和实际成本。
