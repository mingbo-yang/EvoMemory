# EvoMemory：统一事件式记忆机制进化

当前工作流为 `code-memory-hooks-v9`，事件协议为 `memory-events-v1`。所有机制与基线共用 `on_event`。

## 执行与进化

1. 已部署机制在指定学习任务中接收事件，处理当前可见信息，决定是否提供记忆以及如何更新自己的状态。
2. 学习任务完整结束、原生结果和执行证据通过验证后，提交 Task Memory。正常失败的任务也可以成为经历；运行异常不推进有效状态。
3. 固定当前代码、真实状态和有序学习经历，完成当前机制验证与诊断、独立 pre Reviewer，再构造问题查询并检索本轮修改经验。
4. Evolver 读取当前源码、评审证据、允许的日志及检索到的 Evolution Memory，生成完整候选代码、假设与风险。
5. 验证候选，在同一学习经历上建立候选状态，然后进行只读原生评价。Hook 初始输出相同不能作为跳过动态评价的依据。
6. 同一个 Reviewer 评价修改后的证据。固定采纳规则决定是否同时提交候选代码及已评估状态；未采纳时保留父机制。

宿主异常产生独立失败收据并停止测量。候选自身执行失败时，保留执行证据和已验证的逐题结果。配对不完整时，Reviewer、Evolver 和修改经验中的成组均值与差值均为空。每次 Evolver 请求显式携带试验冻结的采纳规则。

紧凑修改经验分别保留父、候选侧与此次改动相关的诊断，并注明各侧省略数量。索引与当前诊断使用相同的评审维度和极性语义。

从已完成的旧源阶段创建新目标实验时，`operations/evolution_study/study.py` 依据每轮绑定的源码、诊断和当时的学习快照重新生成紧凑经验，在新实验中冻结新旧记录映射。两个目标条件继承同一源机制与 Task Memory。

Executor 使用官方 ALMA 循环、动作方法及原生奖励。外围适配器发送事件并更新原有系统记忆槽，不改变行动方法、历史对话或任务步数。TextWorld 在固定 staging 边界补正官方 goal 漏传并保留完整原生观察；真实 Actor 请求保存直接目标送达收据，官方共享源码不改。ALFWorld 上限30步、TextWorld80步；Actor每次512输出tokens、temperature=0、top_p=1。

Reviewer 与 Evolver 是独立角色；Reviewer 不写代码或建议机制、模型用法和任务动作。Reviewer 现有五项标准为忠实性、相关性、可行动性、适用性、效率，意见须绑定实际证据。当前唯一正式采纳规则 `reviewer_and_reward` 要求机制有效、Reviewer 有依据的积极意见，且配对原生验证中候选得分大于 0 并严格高于父机制。其余组合在既定候选次数内继续修改，耗尽后不采纳。历史规则仅用于核验冻结收据。后评审必须保留当前原生分数及首步、末两步轨迹见证；裁剪字段标明哈希和省略量，完整原始日志留档。

Reviewer 的新调用只接收当前父候选的源码、真实记忆及执行证据；历史机制修改记录和旧评审意见交给 Evolver。已有评审仅在其评价对象确实成为当前部署机制、学习日志和记忆状态也一致时复用；未采纳候选的后评审不能充当父机制的当前诊断。

每个展示的功能诊断组必须得到明确判断：支持存在缺陷、未证明存在缺陷或证据不足。判断绑定当前程序、任务、操作范围及真实赋值点见证；缺键、默认值和空初始状态不自动构成缺陷。更短的存储文本不能独立证明保留了有效信息。自由叙述不传给 Evolver；规范事实和意见通过可精确还原的共享引用传递，避免重复元数据挤占反馈预算。

Reviewer 在统一的56000-token输入预算中同时核算完整源码、全部原生结果、聚合计量、最低记忆见证和轨迹片段，包含引用索引开销。必要时对每条轨迹采用相同的较小文本片段预算；原生结果、源码与证据身份保持完整，省略量及原始哈希明确保留。

## 唯一的新机制接口

```python
def on_event(state, event, context):
    # 这里由 Evolver 自主实现；不提供机制设计范例。
    return {"state": new_state, "session": episode_scratch, "memory": memory_response}
```

四类执行事件为 `task_start`、`before_action`、`after_observation`、`task_end`。当前观测、实际发生的动作和反馈按事件提供；终局经历仅在实际结束时提供。`memory` 为 `null` 表示保持记忆槽，`[]` 表示清空，非空 `{id, experience}` 行列表表示替换。`session` 是任务内临时变量，既不是第三层记忆，也不会直接写入长期状态。

已提交的动作在环境转换前被拒时，下一次 `before_action` 可收到 `previous_action_failure`。该次拒绝不产生 `after_observation`。TextWorld 目标送达收据区分本地拦截、传输尝试和成功返回。

机制可以忽略事件。Evolver 只收到接口、字段、可用模型和资源说明，不收到推荐架构、交互时机策略或模型用途建议。现有本地 Embedding/LLM/MLLM 调用接口保留且可选；当前任务仍是文本任务。

历史经历是数据，不是旧机制代码。完整 Hook 日志重放其外部可见事件；没有事件记录的经历只通过明确标记 `history_import` 的 `task_end` 导入。这不是完整动态重放，不伪造任务开始或中间事件。初始离线读取诊断只覆盖 `task_start`。

## 模块职责

| 模块 | 唯一职责 |
|---|---|
| `protocol.py` | 版本、事件名、共享数据字段与整任务预算 |
| `program.py` / `policy.py` / `worker.py` / `isolation.py` | 不可变源码、接口/语言检查、隔离执行 |
| `memory.py` | 持久化状态、快照、统一记忆裁剪和经历导入 |
| `hooks.py` | 单任务临时状态、事件执行、累计资源记录 |
| `hook_adapter.py` | 围绕原 ALMA 循环发送事件、接入同一记忆槽 |
| `native.py` / `textworld_native.py` | 环境启动和原生结果；复用公共记忆收尾与请求证据绑定 |
| `engine.py` | 学习、诊断、提案、验证、评审与采纳的编排 |
| `roles/evolver.py` / `roles/reviewer.py` / `acceptance.py` | 分离的生成、评价和固定采纳规则 |
| `learning.py` / `store.py` | 已提交学习前沿、历史版本及恢复一致性 |
| `experience.py` | 固定的 Evolution Memory 构建与检索 |
| `campaign.py` / `reporting/campaign.py` | 活动实验入口及离线证据报告 |

单次沙箱检查与宿主检查、当前执行与恢复校验跨越不同信任边界，需要保留。去重主要针对同一职责的重复实现，不合并证据与评价、提案与采纳等不同职责。

累计经历归档在宿主端进行有限 JSON 类型校验和复制，不套用单次沙箱输入的2MiB限制。归档不会整体交给生成代码；每次事件、状态、响应与模型请求仍在各自的固定预算边界检查。归档中的完整收据也不能替代事件执行验证。

## 数据和预算

环境之间的两类记忆、机制代码和能力缓存独立。同一环境内跨任务类型继承机制和实际状态，持续积累两类记忆。目标对照从相同源阶段检查点出发，之后分支独立；只有指定学习任务写入 Task Memory，父候选比较及留出均只读。

正式 campaign 必须提供当前版本的持续学习协议和每轮学习任务；缺省或旧冻结记忆配置直接拒绝，不再静默切换流程。旧跨环境划分入口和枚举配置修改经验不进入当前实验。

持续状态16384 tokens、单记忆槽2048 tokens/最多4条；临时session2048 tokens。每任务累计变化记忆槽预算8192 tokens（每次变化按完整新槽计费；单槽上限独立）、最多8次辅助模型broker调用、生成执行CPU20秒/执行墙钟60秒（可信启动和模型等待另记）。单事件含挂起重放累计生成执行CPU1秒/执行墙钟5秒；每个隔离worker另有总CPU1秒内核限制。完整worker CPU保留为实际成本，不能将可信启动开销误算成机制执行。具体数值统一来自 `protocol.py` 与沙箱契约。

Evolver 提案 temperature=0.7、输出6144 tokens；Reviewer temperature=0、输出3072 tokens。接口检查只针对统一事件契约；不合法的提案保留失败与成本。旧 read 专用纠错器已删除，不再额外尝试仅适用于旧接口的修复。

Evolution Memory 使用单一紧凑格式：观测问题、定位代码片段、原生验证结果、规范评审意见、适用环境/类型与证据哈希。完整源码、差异和原报告留在证据档案，不将任务答案、记忆正文或原始轨迹作为跨类型修改经验复制。单条最多1400 tokens，每轮总计3072 tokens、最多4条，使用真实 tokenizer 核算；片段优先显示静态错误和执行诊断对应行，并记录完整范围、遗漏数量及原差异哈希。

源经验和本地经验使用相同问题匹配规则，不按成功或源身份加分，不给任务类型自动匹配优势；完整提供的上一提案不重复占用检索预算。每轮保存排名、实际 token 数、选择或遗漏原因，并与真实模型请求核对。

受限语言规则和模型可见说明共用同一规则源。允许直接对安全类型或静态类型元组进行 `isinstance` 检查；类型对象不能别名化或用于反射。异常只允许静态捕获 `ValueError`、`TypeError`、`KeyError`、`IndexError`，不能绑定异常对象、裸捕获、`raise` 或 `finally`。资源上限、能力契约与模型调用限制走不可捕获的可信终止通道，失败不会提交状态。内部 `state` 可自行组织，外部 `memory` 行仍严格要求 `{id, experience}`。

失败反馈沿用原有进化轮次传递：下一轮收到上一提案的完整源码、准确验证错误、绑定原程序与快照的执行事实，以及已校验的 Reviewer 意见。未通过语法或提案格式检查的原始源码也保留；这不会部署失败候选或继承其状态，也不增加同轮重试。当前已部署源码始终是修改基准。可选日志可按预算省略，完整源码和必需反馈不会静默截断。

事件字段说明统一来自 `protocol.EVENT_CONTRACT`：当前环境信息属于 `event.visible`，`context` 仅包含运行元数据。诊断保留原生字段的实际存在情况，不补造 `goal`。Reviewer 保留完整当前目标、独立首尾文本片段与省略区间、Actor 送达收据；默认表达式求值和实际采用分别记录。父候选有限输入行为比较仅提供事实，不跳过原生验证或改动采纳。空值与缺键是执行事实，是否构成质量问题仍由 Reviewer 结合证据判断。

Actor 上下文检查由 `evomem.actor_transport` 统一处理：保留 32768 tokens 上限与 1024 tokens 预留，超限在本地返回标准 `context_length_exceeded` 响应，使官方 ALMA 已有终止分支收到真实原因。拒绝收据标记 `network_request_sent=false`，不计为实际模型调用，不生成已验证任务分数，不提交 Task Memory。不得截断行动历史、提高上限或将 SDK 包装后的连接错误当成机制效果。

代码、prompt、依赖、模型、参数、任务划分和实际状态均进入运行绑定。新代码不能恢复旧冻结运行；旧结果保持原样。每次搜索的提案次数从冻结协议的 `rounds_per_search` 读取，并与学习块数一致；框架故障的重跑也计入原授权总预算。工程检查通过不等于机制效果或泛化收益成立。

## 准备与运行

工作目录必须是项目根目录，先按根目录 README 安装环境：

```bash
PYTHONHASHSEED=0 python -B -m phase1_codegen --help
```

`python -m phase1_codegen` 与 `python -m phase1_codegen.campaign` 调用同一入口，阶段依次为 `collect`、`source`、`transfer`、`target`、`generalization`，通过 `--root` 指定新目录，`--environment` 指定环境。

`python -m phase1_codegen.prepare_continual --from-root <旧划分目录> --out <全新计划目录>` 只读取任务元数据生成计划，不运行模型或读取旧任务结果。复用已用划分只能作为开发验证，不能称为新独立盲测。计划显式保存统一工作流和 Hook 版本。

活动入口没有旧 `validate-config/run/inspect/legacy` 命令。历史运行在原冻结项目复现。常规双卡实验使用 GPU0/8140 与 GPU2/8142，单独授权的 GPU1 验证可显式指定本机 8141 端口。

可选多模态能力需要单独准备 `.local/multimodal-runtime` 及其模型资产，公开包不包含这些运行时。缺少资产时，按根目录示例显式设置 `EVOMEMORY_ENABLE_OPTIONAL_MODELS=0`，并记录不同的能力目录配置。
