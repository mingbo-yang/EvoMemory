# 六类 ALFWorld 混合进化实验（v4）

六类任务交错进入同一条进化序列。一个模型的一组实验只有一份记忆机制代码、一套 Reviewer 和 Evolver 策略、一份 Evolution Memory。Actor 固定。任务记忆按 simple、two、heat、cool、clean、light 分为六个独立库。每道题的机制只读写本族内容，换机制时也按原任务族回放。两个角色可以综合六族反馈，提出适用于全部任务的修改。

Reviewer 拥有独立版本的诊断准则，Evolver 拥有独立版本的提案程序和提示。初始策略从 v3 的并行实验提交 `73b9726` 派生。在同一张卡上依次运行四组，每组从相同初始机制与空记忆独立开始。各组共享注册题目和配对种子，分别保存搜索历史、模型请求、实际费用与候选回执。

| 组 | Reviewer 可修订 | Evolver 可修订 |
|---|---|---|
| A | 否 | 否 |
| B | 是 | 否 |
| C | 否 | 是 |
| D | 是 | 是 |

完整协同方法对应 D 组。一轮初筛只评当前组合产生的记忆候选，元比较只评当前组合与本轮自然提出的组合。B、C 的单角色对照各自单独运行完整实验。每轮的晋级条件不要求额外运行交叉组合。

## 每轮如何采纳

1. 完成本轮注册的学习题，封存当前母体机制、任务记忆快照和执行记录。当前 Reviewer 诊断，当前 Evolver 提三个候选，与母体在初筛的新题上实测。
2. 开放修订的角色分别根据各自现行策略、公共证据和初筛结果判断是否更新。两者都不申请时沿用原策略。若两者都申请，其中一份修订无效时回退该次联合修订。角色可以根据证据仅申请修改其中一方。
3. 元比较从初筛前的同一母体和同一记忆快照出发。旧、新 Reviewer 分别用各自的策略诊断相同的原始记录与初筛反馈。相同策略可以复用相同诊断，不同策略独立发起诊断请求。旧、新 Evolver 各自接收本侧诊断，并以配对种子各提三个候选。生成源码、接口修复、候选隔离和原生环境计分沿用 v3。
4. 在另一组全新的复筛题上比较双方最佳有效后代。两侧都有可比结果且新侧严格多解题时，提交新策略组合。平局、落败、不可比均沿用旧组合。另在晋级侧后代、共同母体及初筛保留机制中选择实际部署的记忆机制。这样可以分别记录优化器胜负和部署机制胜负。基础设施故障依照原生流水线恢复。
5. 下一轮使用已采纳的角色版本来诊断、提案、反思及修订自身，并能引用上轮的后代得分和采纳决定。审计核对证据、角色输出、候选请求、环境回执、版本以及提交结果。

## 数据与终测

种子为 42。每六个连续的学习或筛选游戏各覆盖一个任务族，块内顺序由种子确定。同一模型的四组和两个基础模型都使用同一张题单及配对种子，记忆和进化历史分别独立。每轮最多跑四路候选评测。

| 用途 | 轮数 | 每次题数 | 六族分配 | 登记的不同游戏 |
|---|---:|---:|---|---:|
| 学习 | 10 | 60 | 各 10 | 600 |
| 初筛记忆机制 | 10 | 60 | 各 10 | 600 |
| 复筛优化策略 | 最多 10 | 60 | 各 10，仅在自然触发后使用 | 600 |
| 四组选优 | 1 | 30 | 各 5 | 30 |
| 冠军与初始机制配对终测 | 1 | 100 | simple、two、heat、clean 各 17，cool、light 各 16 | 100 |

1,930 个游戏按游戏文件、内容哈希及任务标识去重。开发全部取自官方 train，并排除所有官方验证内容的哈希。选组用 18 道 valid_unseen 和 12 道 valid_seen，终测的 100 道全部来自 valid_unseen。开发、选组、终测三部分的游戏组互不重叠。没有入选本次留出的官方验证组，其 train 兄弟实例仍可进入开发题池。题量最少的 light 有 303 道合格 train，使用其中的 300 道。v4 从初始状态独立运行。按游戏内容核对，100 道终测题中有 34 道也登记在此前 v3 的 simple/two 终测题单。

每组完成十轮后，在冻结的机制与空任务记忆上做选组评测。将两模型各 30 题的选组成功数相加，成功最多的一组进入终测，平分按 A、B、C、D 顺序。每个模型保留获胜组在该模型上学出的框架。初始机制与冠军分别从六个空任务记忆库开始，在同一顺序的 100 题上配对运行，允许同族记忆在冻结测试中积累。总成功数及各族的初始成功、最终成功、逐题胜负和平局分别报告。晋级仍按总成功数执行，因此某一族的退步应从分族结果中检查。

## 运行与复核

在项目根目录用官方游戏包登记同一条混合序列。

```bash
python -m rsi_paired prepare-coevolution --protocol mixed-10x60 --seed 42 \
  --games data/downloads/alfworld-tw-0.4.2.zip --metadata data/downloads/json_2.1.1_json.zip \
  --out runs/mixed-six-10x60/panel.json
```

用下列协调器复用两张卡上现有的模型进程。三个环境变量分别指向前序双卡实验的结果目录、该实验的冻结代码目录、以及驻留模型身份检查脚本。

```bash
python -m scripts.run_coevolution_pilot --root runs/mixed-six-10x60 \
  --prior "$V3_RUN_ROOT" --prior-source "$V3_SOURCE" --guard "$RESIDENT_GUARD"
```

协调器等待两台 v3 客户端全部结束，核验完成回执、服务身份及空闲状态。两模型先各自跑 D 组第一轮作为原生小测。它使用正式登记的题目和自然触发条件，通过后复用这一轮回执。两卡各自执行四组独立实验，双方的选组数据全部齐全后才解锁冠军终测。

进度在 `status.json`，小测的真实审核结果与是否实际进入复筛在 `native-smoke.json`。选组结果在 `winner.json`，两模型的冻结机制和终测结果在各自的 `final/frozen.json` 与 `final/summary.json`。从项目根目录执行 `python -m rsi_paired.audit <轮次目录>` 可重新审核原生回执。

早期的单族 10×50、two 的 6×30、heat 的 5×23 仍可按各自协议标识复现。`--suite` 仅供旧的 heat 与 two 独立训练、联合选组实验使用。
